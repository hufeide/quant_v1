## 摘要：V1 的核心诊断与改进优先级

V1 用四个月真实模拟盘证明了一件事：**四个形态策略在无环境判断的前提下全部亏损**，合计 -17%，跑输沪深300（-15%）。这个结果本身是有信息量的——它说明问题不在"哪个形态更好"，而在于**整个系统缺少市场状态判断层**。

解说稿结尾已经预告了 V2 的方向："在 V1 的基础上加入 A 到 F 六档市场温度计，根据大盘状态决定能开几只仓"。本报告把这条线索展开成可实施的方案。

### 改进优先级（按预期收益排序）

| 优先级 | 模块 | 改动幅度 | 预期效果 |
|--------|------|---------|---------|
| P0 | 情绪闸门 → 六维市场状态系统 | 重写 | 直接决定开仓/停仓，影响全部账户 |
| P0 | 强者恒强加入动量崩溃刹车 | 中等 | 该账户最大回撤 44.8%，是最大出血点 |
| P1 | 超跌反弹加入质量分层 | 中等 | 该账户亏 24.5%，"接飞刀"风险未被识别 |
| P1 | 卖出风控改为 ATR 自适应 + 分策略差异化 | 中等 | 止损端"一直在漏钱" |
| P1 | 仓位改为波动率目标制 | 中等 | 六账户等权 18% 忽略了个股波动差异 |
| P2 | 缩量回踩多周期共振 | 小 | 该账户表现最稳（-8.7%），边际改善空间小 |
| P2 | 平台突破维持停用，转事件研究监控 | 小 | 已有全市场证据支持停用 |
| P2 | 打分系统因子化改造 | 中等 | 打分预测力弱是已知结论，改造价值有限 |

### 核心结论

1. **情绪的方向比绝对值重要**（解说稿结论）——这条要落实到"情绪变化率"而非"情绪水平"作为闸门输入。
2. **动量策略需要崩溃保护**——强者恒强在 6 月底赚 29%，之后崩到 -28.9%。学术上这是动量崩溃（momentum crash, Daniel & Moskowitz 2016）的典型形态。
3. **反转策略需要质量过滤**——超跌反弹亏 24.5%，说明"跌得多"不等于"会反弹"。A 股的短期反转效应存在但高度依赖流动性和波动率环境。
4. **止损不是免费的**——V1 的 R1（6% 硬止损）占比 > 40%，在高波动环境下会系统性地卖在低点。
5. **打分系统不该承载预测功能**——解说稿已明确"打分预测力弱"，应把打分降级为"排序工具"而非"预测工具"。

## 第 1 章 情绪检测：从单一闸门到六维市场状态系统

这是全系统优先级最高的改进。V1 的情绪闸门只有一个标量分数和两个阈值，信息量不足以支撑开仓决策。

### 1.1 V1 情绪闸门的问题诊断

V1 的实现（`计划.md` 第 2.4、3.5 节）：

```
sentiment_score = 0.45 * 赚钱效应 + 0.35 * 市场温度 + 0.20 * 散户情绪
  score > 52  → 正常开仓
  40 < score ≤ 52 → 每轮最多开 1 只
  score ≤ 40  → 暂停一切新开仓
```

**问题清单**：

| 问题 | 说明 |
|------|------|
| 权重是拍脑袋的 | 0.45/0.35/0.20 无实证依据，三个指标量纲不同直接加权不合理 |
| 无归一化 | "赚钱效应"用涨跌幅，"市场温度"用涨跌家数比，量纲不一致 |
| 无变化率 | 解说稿结论"情绪的方向比绝对值重要"，但公式只用绝对值 |
| 无状态切换 | 从 52 到 40 是线性渐变，实际市场状态是离散的（牛市/熊市/震荡） |
| 无板块结构 | 只看大盘，不看风格（成长/价值、大盘/小盘） |
| 无波动率维度 | 2025 年 6-11 月 A 股波动率结构变化剧烈，闸门完全没捕捉 |
| fail-open 方向存疑 | 数据缺失时放行，在极端行情中可能恰好是最不该开仓的时候 |

### 1.2 学术与业界的情绪指标构建方法

**学术基础**：

Baker & Wurgler (2006, *Journal of Finance*, 引用 6103 次) 奠定了投资者情绪研究的框架：用横截面收益构造情绪指标，证明**情绪高时，高投机性股票相对低投机性股票的溢价更大**。核心不是"情绪高就卖"，而是"情绪影响横截面差异"。

Schmeling (2009, *Journal of Empirical Finance*, 引用 883 次) 做了国际证据，结论一致：**情绪的反向预测能力在各国普遍存在，但强度差异大**。

Ni et al. (2015, *Economic Modelling*, 引用 140 次) 针对中国市场发现：**情绪对收益的影响是非线性的**——极端乐观和极端悲观时的效应强度不同。这意味着线性阈值闸门（>52 / 40-52 / ≤40）天然不是最优形式。

Wu et al. (2021, *Journal of Mathematics*) 针对中国市场发现：**情绪与股价崩盘风险正相关**——情绪越高，未来崩盘风险越大。这支持"情绪过热时降仓"的方向。

**业界实践**：

| 机构/平台 | 情绪指标构成 |
|-----------|------------|
| 东方财富"情绪指数" | 涨跌家数比 + 涨停家数 + 炸板率 + 连板高度 + 炸板次数 |
| 同花顺"情绪温度" | 涨跌家数比 + 涨停/跌停比 + 昨涨停今表现 + 破净股占比 |
| 雪球"恐贪指数" | 融资融券余额变化 + 新开户数 + 成交额 + 基金申购 |
| 高盛/摩根士丹利 PUMP | 资金流向 + 期权 skew + 波动率 + 债券/股票相对强弱 |
| CTA 常用 regime filter | 200 日均线方向 + ADX + 波动率分位 + 横截面离散度 |

**关键洞察**：业界没有一个"标准答案"，但共同点是**多维度、含变化率、含极端值处理**。

### 1.3 建议的六维市场温度计（对应 V2 的 A-F 档）

把单一标量改为六个维度，每个维度输出 `[0, 6]` 的档位（A=0-1, B=1-2, ..., F=5-6），最终合成一个"市场状态"。

#### 维度 1：趋势（Trend）—— A/B/C

| 档位 | 条件 |
|------|------|
| A 强多头 | 沪深300 close > MA20 > MA60，且 MA20 向上，且 close 在 20 日高点 95% 以上 |
| B 弱多头 | close > MA20，但 MA20 走平或 MA20 < MA60 |
| C 空头 | close < MA20，或 close < MA60 |

**计算规范**：MA 用 `min_periods=n` 避免初期噪声；"向上"定义为 `MA20[t] > MA20[t-5]`。

#### 维度 2：动量（Momentum）—— A/B/C

过去 60 个交易日沪深300 的累计收益分位：

| 档位 | 60日收益分位 |
|------|------------|
| A 强势 | > 66% |
| B 中性 | 33-66% |
| C 弱势 | < 33% |

分位用滚动 500 个交易日窗口计算，避免长期漂移导致的分位失真。

#### 维度 3：波动率（Volatility）—— A/B/C/D

20 日年化波动率在历史（滚动 500 日）中的分位：

| 档位 | 波动率分位 |
|------|----------|
| A 低波 | < 25% |
| B 正常 | 25-60% |
| C 高波 | 60-85% |
| D 极高波 | > 85% |

**关键**：波动率维度应影响**仓位大小**而非仅影响开仓许可。高波时自动降杠杆。

#### 维度 4：广度（Breadth）—— A/B/C

全市场涨跌家数比与腾落指标（ADL）：

| 档位 | 条件 |
|------|------|
| A 健康 | 涨跌家数比 > 1.5，ADL 向上 |
| B 中性 | 涨跌家数比 0.8-1.5 |
| C 恶化 | 涨跌家数比 < 0.8，或 ADL 向下 |

#### 维度 5：资金（Flow）—— A/B/C

用成交额突变率和融资余额变化代理（无融资数据时用成交额）：

| 档位 | 条件 |
|------|------|
| A 流入 | 成交额 > 5日均额 × 1.2，且成交额趋势向上 |
| B 中性 | 成交额在 5日均额 × 0.8-1.2 |
| C 流出 | 成交额 < 5日均额 × 0.8，或趋势向下 |

#### 维度 6：情绪（Sentiment）—— A/B/C/D

**替换 V1 的单一分数**，用涨停板系统数据（解说稿提到已有这套系统）：

| 档位 | 条件 |
|------|------|
| A 冰点 | 涨停家数 < 20，跌停家数 > 30，炸板率 > 50% |
| B 低迷 | 涨停家数 20-50 |
| C 正常 | 涨停家数 50-100 |
| D 过热 | 涨停家数 > 100，连板高度 > 7，炸板率 < 20% |

**方向修正（落实"情绪的方向比绝对值重要"）**：额外输出 `Δ情绪 = 情绪[t] - 情绪[t-5]`，正向变化时档位上调半档，负向变化时下调半档。

### 1.4 合成与仓位映射

**合成规则**（不用加权平均，用"否决制"）：

```
1. 波动率 D → 全局仓位上限降至 50%
2. 情绪 D（过热）→ 全局仓位上限降至 60%
3. 情绪 A（冰点）→ 允许逆向策略（超跌反弹）加仓，趋势策略停仓
4. 趋势 C + 动量 C + 广度 C → 全面停仓（退潮期）
5. 其余情况 → 正常仓位
```

**仓位映射表**（这是 V2 的核心输出）：

| 市场状态 | 趋势 | 动量 | 广度 | 情绪 | 仓位上限 |
|---------|------|------|------|------|---------|
| 强牛 | A | A/B | A | C | 100% |
| 牛震荡 | A/B | B | B | C | 80% |
| 弱牛 | B | B | B | B | 60% |
| 震荡 | B | B | B | B | 50% |
| 弱熊 | C | C | B | B | 30% |
| 熊 | C | C | C | A/B | 0%（只卖不买） |
| 恐慌 | C | C | C | A | 0%（逆向策略可试） |

### 1.5 落地实现方案

**数据需求**：

| 数据 | 频率 | 来源 |
|------|------|------|
| 沪深300 日线 | 日 | akshare `stock_zh_index_daily` 或 `index_zh_a_hist` |
| 全市场涨跌家数 | 日 | akshare `stock_zh_a_spot_em()` 计算 |
| 涨停/跌停/炸板家数 | 日 | akshare `stock_zt_pool_em(date=...)` + `stock_zt_pool_previous_em` |
| 连板高度 | 日 | akshare 涨停池 `limit_num` 字段 |
| 全市场成交额 | 日 | 快照 `amount` 列求和 |
| 融资余额 | 日 | akshare `stock_margin_detail_sse`（可选） |

```python

    所有指标均用 rolling 窗口，第 t 日的输出只使用 <= t 的数据。
    """
    def __init__(self, benchmark_df, market_snapshot_df, limit_pool_df):
        ...

    def compute(self, date) -> dict:
        """返回 {trend, momentum, volatility, breadth, flow, sentiment,
                 delta_sentiment, regime_label, position_cap}"""
```

**关键防未来函数规范**：

- MA/分位数用 `rolling(...).max()` 不加 `shift` 时，第 t 日的分母包含第 t 日数据——**这是正确的**（当天收盘后可知）。
- 但"涨跌家数比"必须在收盘后计算，不能用盘中数据——回测中用日线收盘价计算，实盘中只能在 15:00 后更新。

**存储**：`data/sentiment/{YYYYMMDD}.parquet`，字段见上。

## 第 2 章 缩量回踩策略改进

这是 V1 中表现最好的策略（-8.7%，接近大盘），说明形态逻辑基本成立。改进空间在"精度"而非"方向"。

### 2.1 V1 实现的问题

```
触发条件：
  1. 此前有一波上涨，区间涨幅 ≥ 8%
  2. 随后回调 2~8 天（含当日）
  3. 回调期间日均成交量 < 上涨期间日均成交量 × 0.75
  4. 回调最低点不破 MA20
```

| 问题 | 说明 |
|------|------|
| 上涨段起点未定义 | "此前有一波上涨"如何界定起点？V1 未明确，实现会引入主观性 |
| 回调天数范围太宽 | 2-8 天跨度太大，第 2 天的回踩和第 8 天的回踩是完全不同的风险收益结构 |
| 缩量阈值单一 | 0.75 是一刀切，不同波动率环境下合理的缩量程度不同 |
| 无回踩深度约束 | 只要求"不破 MA20"，但贴 MA20 和远低于 MA20 是两回事 |
| 无量价配合验证 | 缩量回调后是否出现放量止跌？V1 没检查 |
| 无板块/大盘配合 | 个股形态好但大盘差，回踩可能变成下跌中继 |

### 2.2 学术基础

**趋势中继逻辑**：上涨趋势中的缩量回调在学术上对应"价格趋势的可持续性"研究。趋势策略的盈利来源是行为金融学中的**处置效应**（Odean 1998）——投资者过早卖出盈利股、过久持有亏损股，导致趋势延续。

**量价关系**：Gallant et al. (1992, *Review of Financial Studies*, 引用 1308 次) 奠定了价格-成交量关系的基础研究。业界共识：**缩量回调是健康的，放量下跌是危险的**。

**均线支撑的有效性**：均线作为支撑/阻力在学术上没有强证据支持其因果性，更多是**自我实现的预言**（交易者共同关注导致行为趋同）。因此"不破 MA20"作为条件是有意义的，但不应赋予过高的预测权重。

### 2.3 改进方案

#### 改进 1：明确定义上涨段起点

用**分形高点**（fractal high）定义上涨段起点：第 `i` 日是分形高点，当 `high[i] > max(high[i-k:i])` 且 `high[i] > max(high[i+1:i+k+1])`，`k=5`。

```
上涨段 = 从最近一个分形低点到最近一个分形高点
区间涨幅 = (high_peak / low_start - 1) × 100% ≥ 8%
```

#### 改进 2：回踩深度分层

把"不破 MA20"细化为三档：

| 档位 | 回踩深度（相对 MA20） | 风险收益特征 |
|------|---------------------|------------|
| 浅回踩 | close 在 MA20 上方 2% 以内 | 趋势最强，但买点不够好 |
| 标准回踩 | close 在 MA20 下方 0% ~ -3% | 最优买点 |
| 深回踩 | close 在 MA20 下方 3% ~ -6% | 趋势可能转弱，需额外确认 |

深回踩需要额外条件：**当日必须收阳线**且**当日成交量放大**（止跌确认）。

#### 改进 3：量价配合验证

新增条件：回调最后一日（或最近两日）出现**放量止跌**信号：

```
放量止跌 = (volume[t] > 1.5 × volume_ma5[t]) AND (close[t] > open[t])
```

如果回调 8 天内始终没有放量止跌信号，则不触发——这说明抛压未释放完毕。

#### 改进 4：多周期共振

加入周线级别确认：

```
周线条件：MA10（约等于周线 MA2）向上，或 close > MA10
```

日线信号 + 周线方向一致时，信号质量显著提升。

#### 改进 5：相对强度过滤

回踩期间个股不能显著弱于大盘：

```
回踩期个股收益 - 同期沪深300收益 > -5%
```

如果个股回踩幅度远超大盘，说明是个股基本面问题而非技术性回调。

### 2.4 参数优化空间

建议做参数敏感性分析，找出稳健区域而非单点最优：

| 参数 | V1 值 | 建议搜索范围 | 敏感度预期 |
|------|-------|------------|-----------|
| 区间涨幅阈值 | 8% | 5%-15% | 中 |
| 回调天数上限 | 8 | 5-10 | 高 |
| 缩量比例 | 0.75 | 0.6-0.9 | 中 |
| 均线周期 | 20 | 10/20/30 | 中 |

**稳健性检验方法**：对每个参数在搜索范围内跑回测，画"参数值 vs 收益率"曲线。如果曲线是尖锐的单峰，说明该参数是过拟合；如果是平坦区域，说明策略对该参数不敏感、更稳健。

## 第 3 章 平台突破策略：论证停用与替代

### 3.1 停用依据已经充分

解说稿明确：

> "平台突破，经过全市场事件研究，收益显著为负，九月起已停止开新仓。"

这个结论有全市场 200+ 交易日的证据支撑。**继续在回测中运行该策略的唯一价值是作为对照组**，验证事件研究方法的可靠性。

### 3.2 学术证据

**突破策略失效的原因**：

1. **A 股的 T+1 制度**：当日买入无法当日卖出，追高买入后即使盘中冲高也无法兑现，隔夜风险完全暴露。
2. **涨停板制度的扭曲**：突破 60 日新高的股票往往已经涨停或接近涨停，次日高开低走的概率高。
3. **流动性冲击成本**：突破时放量买入，但 A 股散户占比高，跟风盘在次日抛售。
4. **套利者的反向操作**：量化机构在突破信号被广泛识别后，会反向交易（提前埋伏、突破日卖出）。

Wan et al. (2015, *PLoS ONE*, 引用 95 次) 研究了中国股市涨跌停触及的统计特性，发现**触及涨停后的价格动态存在显著的均值回归倾向**。

### 3.3 建议

| 行动 | 说明 |
|------|------|
| 保持停用 | 不开新仓 |
| 保留事件研究脚本 | 每月跑一次，监控该形态是否重新有效 |
| 转向"假突破识别" | 如果能识别"假突破"（突破后快速回落），可以做反向策略 |

**假突破反向策略**（仅作为研究备选，不建议实盘）：

```
触发条件：
  1. 当日最高价突破 60 日新高
  2. 但收盘价 < 60 日新高 × 0.99（冲高回落）
  3. 成交量 > 5日均量 × 1.5
信号：次日开盘做空（A 股无做空工具时放弃，或用股指期货对冲）
```

A 股个人账户无做空工具，此策略仅适用于有融券或股指期货权限的账户。**不建议 V2 优先实施**。

## 第 4 章 超跌反弹策略改进

这是 V1 中亏损第二严重的策略（-24.5%）。问题不在"超跌反弹"这个逻辑本身，而在"什么跌都接"。

### 4.1 学术基础

**短期反转效应**是学术上最稳健的市场异象之一：

- Jegadeesh (1990) 和 Lehmann (1990) 独立发现了短期反转效应：过去 1 周到 1 个月的输家在未来短期跑赢赢家。
- 中国市场的反转效应比美国更强（散户占比高、噪声交易多）。Wu (2010, *Review of Quantitative Finance and Accounting*, 引用 84 次) 发现中国市场同时存在短期动量和长期反转，但短期反转效应在 A 股尤为明显。
- Yu et al. (2019, *International Review of Economics & Finance*, 引用 48 次) 直接对比了中国股市的动量与反转策略，结论：**短期（1-4 周）反转显著，中期（3-6 月）动量显著**。

**关键**：反转效应的强度依赖流动性环境。流动性紧张时（如大跌后的缩量环境），反转效应更强；流动性充裕时（如牛市），反转效应减弱甚至消失。

### 4.2 V1 问题诊断

```
触发条件：
  1. 近 10 天内自最高点跌幅 ≥ 15%
  2. 当日收阳线（涨幅 ≥ 1%）
  3. 当日最低价不创新低（不破近 10 日最低）
```

| 问题 | 说明 |
|------|------|
| 跌幅阈值太低 | 15% 在 10 天内意味着日均 -1.6%，对于高波动个股（日均 3-5%）不算极端超跌 |
| 无波动率归一化 | 一只日均波动 2% 的股跌 15% 是正常波动，一只日均波动 8% 的股跌 15% 才是真正的超跌 |
| 无下跌原因过滤 | 基本面恶化导致的下跌和技术性回调都触发，前者会继续跌 |
| 无流动性过滤 | 下跌过程中如果成交量萎缩（缩量阴跌），说明没人接盘，反弹概率低 |
| "不创新低"条件太弱 | 当日最低价不创新低但收盘价接近最低价（长下影线）其实是弱信号 |
| 无大盘配合 | 大盘在下跌趋势中，个股超跌反弹的持续性差 |

### 4.3 改进方案

#### 改进 1：用 ATR 归一化跌幅（核心改进）

```
真实跌幅 = (peak_10d - close) / (ATR14 × sqrt(10))
```

要求真实跌幅 ≥ 1.5（即超过正常波动范围的 1.5 倍）。

**为什么用 ATR**：ATR 度量的是"正常"价格波动范围。跌幅如果只是 1-2 倍 ATR，属于正常波动；超过 3 倍 ATR 才是真正的超跌。

#### 改进 2：下跌质量过滤

下跌过程中不能出现"放量暴跌"（恐慌性抛售）：

```
放量暴跌 = (volume[t] > 2 × volume_ma5[t]) AND (pct_chg[t] < -7%)
```

如果下跌段内出现 ≥ 2 次放量暴跌，说明是恐慌盘出逃，反弹概率降低（除非出现极端超跌后的技术性反抽）。

**反向条件**：如果下跌末段出现"缩量 + 长下影线"，则是好的超跌信号。

#### 改进 3：波动率环境过滤

只在波动率处于正常或偏低状态时做超跌反弹：

```
regime.volatility ∈ {A, B}  # 排除 C（高波）和 D（极高波）
```

高波动环境下的超跌反弹是"接飞刀"——跌得快反弹得也快，但方向不确定。

#### 改进 4：左侧/右侧确认

V1 的"当日收阳线"是左侧信号（当天就买）。加入右侧确认：

```
右侧确认：次日开盘价 > 当日收盘价，且次日收盘不破当日低点
```

右侧确认会牺牲入场价格（买入价更高），但显著提高胜率。建议 A/B 测试左侧 vs 右侧。

#### 改进 5：超跌深度分层

| 档位 | 真实跌幅（ATR 倍数） | 策略 |
|------|---------------------|------|
| 浅超跌 | 1.5-2.5 | 小仓位试探 |
| 标准 | 2.5-4.0 | 正常仓位 |
| 极端超跌 | > 4.0 | 需要额外确认（放量止跌 + 大盘不弱） |

#### 改进 6：反弹目标与止损

超跌反弹的持有期应短于趋势策略：

```
目标：ATR × 1.5（不是固定百分比）
止损：入场价 - 0.5 × ATR
持有期上限：10 个交易日（超跌反弹的持续性有限）
```

### 4.4 验证实验设计

**OS-01 真实跌幅 vs 简单跌幅**：比较 ATR 归一化前后信号质量。

**OS-02 左侧 vs 右侧**：比较当日买入和次日确认后买入的收益差异。

**OS-03 波动率过滤效果**：在高波动环境（regime.volatility = C/D）中排除超跌信号，观察回撤改善。

**OS-04 持有期优化**：持有 5/10/15/20 日的收益分布。

## 第 5 章 强者恒强策略改进

这是 V1 中亏损最严重的策略（-28.9%），也是最戏剧化的（6 月底赚 29%，之后崩到 -28.9%，最大回撤 44.8%）。

### 5.1 学术基础

**动量效应**：Jegadeesh & Titman (1993) 的经典论文证明了中期（3-12 个月）动量效应的存在。后续大量研究确认了这一效应在全球主要市场普遍存在。

**动量崩溃（Momentum Crash）**：Daniel & Moskowitz (2016, *Journal of Financial Economics*) 系统研究了动量崩溃现象：

> 动量策略在市场反弹时表现极差——熊市中的强势股（被做空）在市场反转时暴涨，导致动量组合巨亏。

这与 V1 强者恒强的表现完全一致：6 月底市场反弹时，前期强势股集体暴涨（空头被迫回补），而 V1 的强者恒强是做多前期强势股——但 7-8 月市场风格切换后，前期强势股大幅跑输。

**中国市场的动量特征**：

- Naughton et al. (2007, *Pacific-Basin Finance Journal*, 引用 101 次) 发现中国股市存在动量效应，但周期较短。
- 中国市场的动量效应在**机构持股比例低的股票**上更强（散户驱动）。
- **A 股的动量效应弱于美股**，因为散户占比高导致噪声交易多，趋势持续性差。

### 5.2 V1 问题诊断

```
触发条件：
  1. 近 20 日涨幅 ≥ 25%
  2. 距区间高点回撤 < 8%
  3. 收盘价守住 MA10
```

| 问题 | 说明 |
|------|------|
| 20日 25% 是极端动量 | 年化波动率 40% 的股票，20 日 25% 涨幅是 2 倍标准差以上事件，均值回归概率高 |
| 回撤 < 8% 太宽松 | 强势股从高点回撤 5% 和 7.9% 都是"强势"，但前者是正常波动，后者是趋势转弱 |
| 无动量质量评估 | 涨幅是连续推升还是跳空暴涨？后者更脆弱 |
| 无波动率缩放 | 高波动股票的 25% 涨幅和低波动股票的 25% 涨幅风险完全不同 |
| 无市场环境判断 | V1 完全没有大盘判断，动量策略在熊市反弹中会巨亏 |
| 无止损分层 | 动量策略的止损应比反转策略更宽（趋势策略给波动空间） |

### 5.3 动量崩溃的防范

**这是该策略改进的核心**。

#### 防范 1：市场环境过滤（最重要）

```
只在 regime.trend ∈ {A, B} 时开新仓
regime.trend = C（空头）时，即使个股形态再好也不买
```

强者恒强在 V1 中亏 28.9% 的主要原因是：7-8 月大盘走弱时仍然在买强势股，而这些强势股在大盘转弱后补跌。

#### 防范 2：动量质量评估

区分"健康动量"和"末段动量"：

```
健康动量特征：
  · 20日涨幅中，阳线天数 > 阴线天数 × 1.5
  · 涨幅分布均匀（日涨幅标准差 < 3%）
  · 成交量稳步放大（非突然暴量）
  · 回调时缩量

末段动量特征：
  · 出现单日涨幅 > 9%（加速赶顶）
  · 近 5 日涨幅 > 前 15 日涨幅 × 1.5（后段加速）
  · 成交量突然放大 > 3 倍均量
  · 出现长上影线（冲高回落）
```

末段动量信号触发时，仓位减半或不入场。

#### 防范 3：波动率缩放仓位

```
仓位倍数 = target_vol / (atr14 / close × sqrt(252))
其中 target_vol 设为 25%（年化目标波动）
```

低波动股票仓位大，高波动股票仓位小，使得每笔交易承担的风险（波动率）大致相同。

#### 防范 4：回撤刹车

个股从持仓最高点回撤超过 12% 时，减仓 50%；回撤超过 15% 时清仓。

这比 V1 的 R3（移动止盈）更严格——V1 的 R3 只在浮盈 > 12% 后才激活，但动量崩溃往往发生在浮盈快速蒸发的过程中。

#### 防范 5：持有期上限

动量策略的盈利窗口是有限的：

```
最长持有 30 个交易日，到期后无论盈亏都平仓
```

学术上动量效应的周期是 3-12 个月，但 A 股散户驱动的市场动量衰减更快，30 日是合理上限。

### 5.4 参数优化建议

| 参数 | V1 值 | 建议 | 理由 |
|------|-------|------|------|
| 动量周期 | 20 日 | 20-40 日做敏感性分析 | A 股动量周期可能更短 |
| 涨幅阈值 | 25% | 降低到 15-20% | 25% 是极端事件 |
| 回撤容忍 | 8% | 收紧到 5% | 减少追高 |
| 均线确认 | MA10 | MA10 或 MA20 做对比 | MA10 在震荡市中噪声大 |

### 5.5 验证实验设计

**MO-01 市场环境过滤效果**：加入 regime.trend 过滤前后的收益对比。**预期这是最大的改善来源**。

**MO-02 动量崩溃时段标注**：找出回测中亏损最大的连续 20 日窗口，检查当时的 regime 标签。

**MO-03 持有期优化**：10/20/30/40/60 日的收益分布。

**MO-04 动量质量评分有效性**：健康动量 vs 末段动量分组的收益差异。

## 第 6 章 卖出风控改进

V1 的五条主规则 + 三条兜底是"经验驱动"的设计，有明确的问题可以改进。

### 6.1 学术基础

**止损的有效性争议**：

学术界对止损（stop-loss）的有效性存在分歧：

- 一些研究认为止损能限制下行风险，改善风险收益比。
- 另一些研究指出，在有效市场中，止损等价于"在波动底部卖出"——因为价格触及止损线往往是短期波动极值。
- 行为金融视角：止损纪律能对抗**处置效应**（投资者不愿卖出亏损股），这是其价值所在。

**ATR 止损**：基于波动率的止损（而非固定百分比）在业界被广泛使用，理由是"让止损宽度与市场波动匹配"。高波动时止损宽（避免被洗出），低波动时止损窄（限制亏损）。

**V1 的 R1（6% 硬止损）问题**：

对于日均波动 5% 的股票，6% 止损在 1 个标准差内就会被触发——**这实际上是一个噪声过滤器，不是风控工具**。它会在正常波动中频繁触发，把好股票洗出去。

### 6.2 V1 各规则诊断

| 规则 | 诊断 | 建议 |
|------|------|------|
| R1 6%止损 | 对高波动股太紧，对低波动股太松 | 改为 ATR 自适应：`止损 = entry - 1.5 × ATR14` |
| R2 保盈止损 | 逻辑合理，但 7%/3% 阈值是拍脑袋 | 改为 ATR 倍数：浮盈曾达 `1.0 × ATR`，回落至 `0.3 × ATR` |
| R3 移动止盈 | 回撤 5% 太紧，容易在震荡中被洗 | 改为 `回撤 = 2 × ATR`，或固定 8% |
| R4 硬止盈 18% | 对低波动股永远不触发 | 改为 `浮盈 = 3 × ATR` |
| R5 跌停保护 | 实现正确，保留 | — |
| B1 跌破 MA20 | 有未来函数风险（收盘确认需要盘中判断） | 用"收盘价 < MA20 且 连续 2 日"替代 |
| B2 时间止损 20日/9% | 逻辑合理但 9% 门槛可能太高 | 结合 ATR 调整 |
| B3 跌停顺延 | 实现正确，保留 | — |

### 6.3 ATR 自适应止损实现

```python
class ATRStopManager:
    """基于 ATR 的自适应止损"""

    def __init__(self, atr_period=14, stop_mult=1.5,
                 breakeven_gain=1.0, breakeven_loss=0.3,
                 trailing_gain=2.0, trailing_drawdown=1.5,
                 hard_gain=3.0):
        self.atr_period = atr_period
        self.stop_mult = stop_mult        # 初始止损 = atr × 1.5
        self.breakeven_gain = breakeven_gain   # 浮盈达 1×ATR 后保盈
        self.breakeven_loss = breakeven_loss   # 回落至 0.3×ATR 触发
        self.trailing_gain = trailing_gain     # 浮盈达 2×ATR 激活移动止盈
        self.trailing_drawdown = trailing_drawdown  # 自高点回撤 1.5×ATR
        self.hard_gain = hard_gain       # 浮盈达 3×ATR 硬止盈

    def check(self, position, bar):
        atr = position.atr  # 持仓期间的 ATR 基准
        entry = position.entry_price
        peak = position.peak_price
        current = bar.close

        pnl_atr = (current / entry - 1) / atr  # 归一化盈亏
        drawdown_atr = (peak - current) / atr  # 归一化回撤

        if pnl_atr >= self.hard_gain:
            return "R4_HARD_PROFIT"
        if pnl_atr >= self.trailing_gain and drawdown_atr >= self.trailing_drawdown:
            return "R3_TRAILING"
        if pnl_atr >= self.breakeven_gain and pnl_atr <= self.breakeven_loss:
            return "R2_BREAKEVEN"
        if (entry - current) / entry >= self.stop_mult * atr / entry:
            return "R1_STOP_LOSS"
        return None
```

**ATR 基准的选择**：用建仓日的 ATR14 作为基准（固定值），而非每日更新的 ATR——后者会导致止损线随波动率变化而漂移，难以管理。

### 6.4 分策略差异化风控

不同策略的持仓逻辑不同，风控参数也应不同：

| 策略 | 止损宽度 | 原因 |
|------|---------|------|
| 缩量回踩 | 1.0 × ATR | 趋势策略，给波动空间 |
| 平台突破 | — | 已停用 |
| 超跌反弹 | 0.5 × ATR | 反转策略，止损紧 |
| 强者恒强 | 2.0 × ATR | 动量策略，给最大空间 |

```python
  "entry_date": "2025-08-01",
  "entry_price": 10.50,
  "exit_price": 9.82,
  "return": -6.5%,
  "reason": "R1_STOP_LOSS",
  "atr_at_entry": 0.35,
  "stop_distance_atr": 1.5,  # 止损距离是 1.5×ATR
  "market_regime_at_exit": "弱熊",  # 卖出时的市场状态
  "holding_days": 10,
}
```

**诊断指标**：

| 指标 | 计算 | 健康标准 |
|------|------|---------|
| R1 占比 | R1 卖出笔数 / 总卖出笔数 | < 30% |
| 止损后反弹率 | R1 卖出后 5 日内反弹（涨幅 > 3%）的比例 | > 50% 说明止损太紧 |
| 平均止损亏损 | R1 卖出的平均亏损幅度 | 接近 1.5 × ATR |
| 移动止盈后继续上涨率 | R3 卖出后 5 日内继续上涨比例 | < 30% 说明止盈合理 |

**止损后反弹率 > 50% 是一个明确的"止损太紧"信号**。如果出现这种情况，应放宽止损参数。

### 6.6 验证实验设计

## 第 7 章 仓位与组合管理

### 7.1 V1 仓位规则的问题

```
每账户最多持有 6 只
每只目标仓位 18%
每轮最多买 2 只
每天最多买 3 只
```

**问题**：

1. **等权 18% 忽略波动率差异**：一只年化波动 20% 的股和一只年化波动 60% 的股各占 18%，后者对组合的风险贡献是前者的 3 倍。
2. **无相关性控制**：6 只股票如果都属于同一板块（如都是科技股），实际分散度远低于 6 只随机股票。
3. **无总仓位上限**：理论上 6 × 18% = 108%，超过 100% 不可能，但接近满仓在高波动环境下很危险。
4. **建仓节奏固定**：分 10 日建满，不考虑当时的市场状态。

### 7.2 波动率目标仓位

**核心思想**：每只股票的仓位反比于其波动率，使得每只股票对组合的风险贡献大致相同。

```
仓位_i = (target_vol / vol_i) × (1 / N) × 总仓位上限

其中：
  target_vol = 年化目标波动率（如 30%）
  vol_i = 股票 i 的年化波动率（ATR14/close × sqrt(252)）
  N = 持仓数量
```

**举例**：

| 股票 | 年化波动率 | 仓位倍数 | 实际仓位 |
|------|----------|---------|---------|
| A | 25% | 30/25 = 1.2 | 18% × 1.2 = 21.6% |
| B | 40% | 30/40 = 0.75 | 18% × 0.75 = 13.5% |
| C | 60% | 30/60 = 0.5 | 18% × 0.5 = 9% |

低波动股票仓位大，高波动股票仓位小，总仓位可能不满 100%（留出现金缓冲）。

### 7.3 相关性控制

**行业集中度限制**：

```
同一行业（申万一级）的持仓总权重 ≤ 40%
```

**风格集中度限制**：

```
同一风格（如都是高动量或都是高反转）的持仓总权重 ≤ 50%
```

实现方法：持仓前检查新买入股票与现有持仓的行业/风格标签，如果集中度超限则跳过。

### 7.4 Kelly 与分数 Kelly

**Kelly 公式**给出在已知胜率和盈亏比时的最优仓位：

```
f* = p - q / b

其中：
  p = 胜率
  q = 1 - p = 败率
  b = 盈亏比（平均盈利 / 平均亏损）
```

**问题**：Kelly 需要精确估计 p 和 b，而这在实战中不可能做到。而且 Kelly 是"最优"仓位，实际应使用**分数 Kelly**（如 0.25 Kelly 或 0.5 Kelly）以降低参数误差风险。

**实用建议**：

| 场景 | 仓位建议 |
|------|---------|
| 信号质量高（历史胜率 > 60%） | 0.5 Kelly |
| 信号质量中等 | 0.25 Kelly |
| 信号质量低（< 50%） | 不交易 |

**Kelly 在 V1 中的应用**：不建议直接用 Kelly 定仓位，但可以用它作为**仓位上限的参考**——如果某策略的历史 Kelly 分数 > 10%，说明该策略的杠杆风险已经很大，应人工干预。

### 7.5 建仓节奏改进

V1 的"分 10 个交易日建满目标仓位"过于机械。建议改为：

```
建仓节奏 = f(regime.volatility, regime.trend)

低波动 + 强趋势 → 快速建仓（3-5 日）
高波动 + 弱趋势 → 缓慢建仓（10-15 日）
极端波动 → 暂停建仓
```

### 7.6 验证实验设计

**PM-01 波动率目标 vs 等权**：对比两种仓位方案的波动率、回撤、收益。

**PM-02 相关性限制效果**：加入行业集中度限制前后的回撤对比。

**PM-03 建仓节奏敏感性**：3/5/10/15 日建仓的收益和回撤差异。

## 第 8 章 打分系统改造

### 8.1 V1 打分的问题

```
综合得分 = 0.30×形态契合度 + 0.20×均线趋势 + 0.15×缩量健康度 +
           0.15×相对强度 + 0.10×回踩位置 + 0.10×MACD
```

解说稿已明确："打分的预测力很弱，分数高不代表涨得多，真正有区分度的是具体形态特征。"

**为什么预测力弱**：

1. **权重无实证依据**：0.30/0.20/0.15... 是主观设定。
2. **因子之间高度相关**：均线趋势、MACD、形态契合度都包含"趋势"信息，加权后重复计权。
3. **量纲不一致**：形态契合度是 0-100 的整数，相对强度是百分位，缩量健康度是 0-1 的比率。
4. **买入条件反向使用**：`得分 < 70 才买`——这个规则本身说明高分股表现差，但为什么差？是打分系统的问题还是高分股本身的特点？

### 8.2 从规则打分到因子化

**建议：把打分系统降级为"排序工具"，不作为预测工具。**

具体做法：

1. **停止使用"得分 < 70"作为买入条件**。这个条件引入了人为的断点，且理由不充分。
2. **打分仅用于同形态内的排序**：比如在 10 只缩量回踩信号中，用打分排序选出前 3 只。
3. **验证打分的排序能力**：计算打分与未来收益的 Spearman 相关系数（而非 Pearson），看排名是否有效。

### 8.3 因子化改造方案

如果要保留打分系统，建议做以下改造：

**因子预处理**：

1. **标准化**：每个因子做横截面 z-score 标准化。
2. **去相关**：用 PCA 或因子正交化去除因子间相关性。
3. **等权或 IC 加权**：用历史 IC（信息系数）作为权重，而非主观权重。

**IC 加权方法**：

```
对每个因子 f，计算历史 IC：
  IC_f = mean(corr(factor_f[t], return[t+1])) over t

权重 w_f = max(0, IC_f) / sum(max(0, IC_f))
```

**预期结果**：改造后的打分系统的预测力会提升，但可能仍然有限——因为形态信号本身的预测力就弱。**不应期望打分系统能产生超额收益**。

### 8.4 验证实验设计

**SC-01 打分 vs 收益相关性**：计算 V1 打分与未来 1/5/10 日收益的 Spearman 相关系数。预期不显著。

**SC-02 分组收益**：按得分分四组（Q1-Q4），比较各组平均收益。预期 Q1（最低分）和 Q4（最高分）差异不大。

**SC-03 IC 加权 vs 等权**：比较两种权重方案的排序能力。

**SC-04 打分排序价值**：在同形态信号内，打分前 30% 的选股表现是否优于后 30%。

## 第 9 章 回测方法论改进

V1 计划中已经列出了 9 个消融实验（AB-01 ~ AB-09），这是好的。但回测方法本身有几个需要补充的要点。

### 9.1 幸存者偏差

**问题**：如果回测的股票池是"当前存在的股票"，那么已经退市的股票不会被包含，回测结果会高估。

**A 股的特殊性**：A 股退市率近年上升（2020 年 16 只，2021 年 23 只，2022 年 46 只，2023 年 71 只），幸存者偏差的影响在增大。

**解决方法**：

1. 用历史某个时点的股票列表（point-in-time universe），而非当前列表。
2. akshare 的 `stock_info_a_code_name()` 返回的是当前列表。要获取历史列表，需要用 `stock_info_sh_name_code()` 和 `stock_info_sz_name_code()` 并结合历史数据的存在性判断。

**实现**：

```python
# 对每个交易日 t，只使用在 t 日有数据且在 t 日之前已上市的股票
# 这需要拉取全历史数据后，对每只股票确定其上市日期
```

### 9.2 前视偏差（Look-ahead bias）

V1 的 `src/indicators.py` 已经做了 lookahead 防护（"第 i 行的结果只使用 <= i 的数据"）。需要检查的其余风险点：

| 风险点 | 检查方法 |
|--------|---------|
| MA 计算 | 确认用 `rolling(min_periods=n)`，前 n-1 行是 NaN |
| 60 日新高 | 确认用 `rolling(60).max().shift(1)`，不含当日 |
| 涨停家数 | 确认用当日收盘状态，不含盘中触及 |
| 换手率 | 确认用当日收盘数据，不含盘中 |
| 成交额排序 | 确认用当日收盘后的快照，不含盘中 |

### 9.3 回测过拟合

**问题**：V1 有大量可调参数（6 个打分权重、4 个形态阈值、5 条风控规则、20+ 个子参数）。在历史数据上反复调参会引入过拟合。

**防御方法**：

1. **样本外验证**：把回测区间分成训练集（2025-06 ~ 2025-09）和验证集（2025-09 ~ 2025-11）。
2. **参数敏感性分析**：如果最优参数在敏感性分析中是尖锐的单峰，说明过拟合。
3. **Deflated Sharpe Ratio**：考虑尝试的策略数量，调整 Sharpe 的显著性阈值。

**Deflated Sharpe Ratio 简化实现**：

```
如果有 N 个策略被测试，期望的最大 Sharpe 为：
  E[max Sharpe] ≈ sqrt(2 × ln(N)) × σ_annual / sqrt(T)

其中 T 是年化因子（如 252 个交易日）。
```

如果策略的 Sharpe 不超过这个期望值，说明该策略的表现可能只是"尝试了 N 次后最好的结果"，而非真正的 alpha。

### 9.4 交易成本建模

V1 已列出佣金/印花税/过户费。补充要点：

| 成本项 | V1 考虑 | 补充 |
|--------|---------|------|
| 佣金 | 万 2.5，最低 5 元 | — |
| 印花税 | 卖出 0.1% | — |
| 过户费 | 万 0.1 | — |
| **冲击成本** | 未考虑 | **重要**：大额订单的滑点 |
| **涨跌停无法成交** | 已考虑（R5） | — |

**冲击成本估算**：

```
冲击成本 ≈ 0.1% × (订单金额 / 当日成交额) × sqrt(252)
```

对于 V1 的单账户 100 万、目标仓位 18% = 18 万，如果目标股当日成交额 5 亿，冲击成本约 0.01%——可以忽略。但如果买小盘股（成交额 5000 万），冲击成本约 0.1%——不可忽略。

### 9.5 分钟级 vs 日线级回测的差异

V1 是日内 2 分钟轮询系统，但回测用日线。这个差异需要量化：

| 差异 | 影响 |
|------|------|
| 日内开仓时间 | 日线回测假设当日收盘价买入，实际可能在 09:40-14:57 之间的任何时刻买入 |
| 日内卖出触发 | 日线回测无法捕捉日内触及止损后的卖出 |
| 涨跌停 | 日线回测无法区分"盘中封死"和"收盘封死" |

**缓解方法**：

1. 对于买入，假设以次日开盘价成交（保守估计）。
2. 对于卖出，用当日 OHLC 判断是否触及止损/止盈，如果触及则假设以触发价成交（需要估算触发时点）。

## 第 11 章 工程可靠性：五条铁律的深化与扩展

V1 沉淀的五条铁律是系统能"无人值守跑四个月"的根本保障。解说稿提到"V1 在这上面踩过很多坑"，说明这些不是理论推演，而是真实故障换来的。本章把这五条展开成可测试的规范，并指出 V1 尚未覆盖的失效模式。

### 11.1 F1 绝不用过期价格成交

**V1 实现**：价格带 `timestamp`，与当前时间差 > 30s 视为过期 → 本轮不动。

**30 秒阈值的合理性分析**：

2 分钟一轮的调度，如果价格缓存是上一轮拉取的，实际延迟可能达到 2 分钟以上。30 秒阈值确实能拦住大部分陈旧数据，但存在一个盲区：**网络请求本身可能挂起**。如果某轮快照拉取耗时 90 秒（接口慢），拿到的价格实际是 90 秒前的，但 `timestamp` 会被写成拉取完成时刻——过期检查失效。

**改进：双时间戳机制**：

```
每条价格记录携带两个时间：
  fetch_ts   = 请求发出时刻
  recv_ts     = 响应接收时刻
有效年龄 = now - recv_ts
数据新鲜度 = recv_ts - fetch_ts   （用于监控接口延迟）

过期判定：now - recv_ts > 30s  →  本轮不动
超时判定：recv_ts - fetch_ts > 5s  →  记录告警，本轮用上一有效价格
```

**更根本的问题：轮询式架构的固有延迟**

2 分钟轮询意味着任意时刻看到的行情最老可能有 2 分钟。对于"实时价 ≤ 选股时价 × 1.03"这类约束，延迟会系统性地影响成交价。

**改进方向**：把"每 2 分钟轮询"改为"事件驱动"——只在价格变化超过阈值时触发引擎。对 600 只候选股，实际有交易价值的行情变化远少于全量刷新。

**验证实验 ENG-01**：统计回测中 F1 触发次数及其对成交价的影响。如果 F1 频繁拦截（> 10% 的轮次），说明数据源延迟是主要摩擦，应优先改善数据通路而非调参。

### 11.2 F2 跌停卖不出就是卖不出

**V1 实现**：模拟撮合检查跌停封单，不造假成交，挂单顺延至开板。

**这个设计的决策价值很高**。反面案例在量化社区反复出现：为了"好看"的回测曲线而假设跌停能成交，导致回测收益被严重高估。A 股跌停封单排队，实际成交可能要等数日。

**V1 未覆盖的三种情况**：

| 情况 | 说明 | 处理建议 |
|------|------|---------|
| 连续跌停 | 跌停封死多日，持仓无法卖出 | 必须顺延，同时仓位冻结期间不能买入新标的（避免现金被占） |
| 跌停开板后再次封死 | 开板短暂成交窗口内未卖出 | 保留挂单状态，继续顺延 |
| 尾盘开板 | 14:57 开板但来不及成交 | A 股 15:00 收盘，此时挂单实际成交概率低 |

**实现要点**：

```
持仓状态机：
  可交易 → 触发卖出 → 跌停封死 → 挂单中（冻结）→ 开板 → 成交 → 可交易
                                    ↓
                              开板窗口错过 → 继续挂单
```

**冻结期间的仓位计算**：挂单中的持仓应视为"已卖出但未到账"，不计入可用仓位，但现金尚未增加——这会造成仓位比例暂时失衡。建议冻结期间暂停该账户的新开仓（比 V1 的全局 `buy_halt` 更精准）。

**验证实验 ENG-02**：统计回测中跌停顺延天数分布。如果 P99 顺延天数 > 5 日，说明该规则对资金效率影响显著，需重新评估单票 18% 的仓位上限。

### 11.3 F3 股票池落后立即停止买入

**V1 实现**：池数据 `last_update` 落后 > 1 轮 → `buy_halt = True`。

**问题：1 轮的阈值与 2 分钟调度绑定，缺乏绝对时间维度**。如果系统因为某原因停了 5 分钟（3 轮未更新），F3 会触发；但如果停的是 1 分钟（1 轮内），F3 不触发——而 1 分钟内行情可能已经大幅变化。

**改进：双阈值**：

```
buy_halt 触发条件（任一满足）：
  · 落后轮次 > 1 轮           （V1 原有）
  · 落后绝对时间 > 60 秒      （新增，防止调度间隔本身变长时漏判）
```

**更深层问题：停止买入后是否应该恢复？**

V1 只定义了如何停，没定义如何恢复。如果数据源持续故障 30 分钟，系统会一直 halt 到数据恢复——但恢复的那一刻可能正好是该跑风控的时点。

**建议：恢复时跑一次全量补算**，而非简单解除 halt：

```
halt 解除后：
  1. 拉取最新快照
  2. 用最新数据重算全部持仓的风控状态（可能错过的止损）
  3. 重算候选池（可能错过的信号）
  4. 两步都成功后才允许正常交易
```

**验证实验 ENG-03**：构造数据中断场景，测试恢复逻辑是否正确触发补算。

### 11.4 F4 看门狗独立巡查

**V1 实现**：独立进程每 10 分钟巡查三件事：① 价格是否刷新 ② 股票池是否更新 ③ 交易引擎是否真正跑完。

**"独立"是关键设计**。如果看门狗和主引擎在同一进程内，主引擎死锁或死循环时看门狗也无法运行——V1 明确要求独立进程，这是对的。

**V1 未覆盖的失效模式**：

| 失效模式 | 说明 | 检测方法 |
|------|------|---------|
| 看门狗自身失效 | 看门狗进程挂了，没人检查看门狗 | **双层看门狗**：外层用系统级 cron/systemd 检测看门狗进程存活 |
| 假活（zombie） | 主引擎进程存在但不产生输出 | 检查**输出文件的时间戳**而非进程是否存在 |
| 磁盘写满 | 引擎跑完但结果写不进文件 | 检查输出文件大小是否为 0 或写入失败日志 |
| 时间漂移 | 系统时钟不准导致时间闸门失效 | NTP 同步检查 + 交易时段校验 |

**"跑完"的定义需要精确**：进程退出码为 0 不等于"跑完了"。建议看门狗检查：

```
引擎完成标志 = 当日结果文件存在
              且 文件最后修改时间 > 引擎启动时间
              且 文件大小 > 最小阈值
              且 结果中记录的轮次数量 == 预期轮次数量
```

**改进：状态文件机制**。主引擎每轮结束写一个心跳文件，包含轮次号、完成时间、持仓快照摘要。看门狗只需检查心跳文件，比检查多个输出文件更可靠。

```
heartbeat = {
  "pid": 12345,
  "round": 47,           # 今日已完成第几轮
  "ts": "2025-08-15T10:32:00",
  "positions_hash": "a3f9...",  # 持仓快照哈希，用于检测持仓是否意外变化
  "expected_rounds": 168,
}
```

### 11.5 F5 收盘自检长期零成交告警

**V1 实现**：某策略连续 N 个交易日零成交 → 主动告警。

**这个规则的价值被低估了**。零成交可能意味着：

| 可能原因 | 诊断方法 |
|---------|---------|
| 策略逻辑错误（信号永远不触发） | 检查候选池中该形态的触发次数，而非成交次数 |
| 买入约束全部拦截（得分/时间/价格） | 检查被各约束拦截的数量分布 |
| 情绪闸门长期关闭 | 检查 regime_label 分布 |
| 数据问题（字段缺失导致条件恒假） | 检查候选池数据的非空率 |
| 市场确实没有该形态 | 检查全市场该形态的触发次数 |

**关键区分：零信号 vs 零成交**。

```
诊断链：
  零成交 ← 分叉 ─→ 零信号  → 形态检测器问题 或 市场无该形态
              ─→ 有信号零成交 → 检查拦截原因：
                  · 得分 ≥ 70 拦截？      → 打分阈值问题
                  · 09:40 前无信号？      → 信号集中在开盘？
                  · 价格 > 选股价 × 1.03？→ 追高约束过紧
                  · 30 日冷却期拦截？    → 频繁交易同一股票
                  · buy_halt 拦截？       → F3 触发
```

**建议：把告警阈值从"N 日"改为分阶段**：

```
连续 3 日零成交  →  WARNING（记录诊断链各项计数）
连续 10 日零成交 →  CRITICAL（推送告警）
连续 20 日零成交 →  AUTO_DISABLE（自动停用该策略并通知）
```

自动停用是有争议的（可能正好在市场不提供该形态时停用），但配合人工确认机制是合理的。

### 11.6 V1 未覆盖的工程失效模式

解说稿说"V1 踩过很多坑"，但五条铁律之外仍有已知的工程风险：

**进程级**：

| 风险 | 说明 | 防护 |
|------|------|------|
| 重复执行 | cron 任务重叠（上一轮没跑完下一轮已启动） | PID 文件 + 运行时长上限 |
| 状态丢失 | 进程重启后内存状态清空 | 每轮结束落盘状态（positions、cooldown、peak_price） |
| 幂等性 | 同一笔成交被记录两次（推送重试） | 成交记录唯一键（code + ts + side） |

**数据级**：

| 风险 | 说明 | 防护 |
|------|------|------|
| 数据源静默返回错误数据 | 接口不报错但返回空表或错表 | 快照行数监控（< 3000 行告警） |
| 主备切换不干净 | 主源失败切到备源，但备源数据口径不同 | 切换时校验字段一致性（如 close 价格差异 > 5% 告警） |
| 除权日价格跳空 | 前复权数据处理不当导致指标失真 | 除权日标记 + 当日指标不参与信号判断 |
| 复权因子错误 | akshare 拉取的前复权数据在分红后回溯失效 | 定期重算历史数据的复权因子 |

**资金级**：

| 风险 | 说明 | 防护 |
|------|------|------|
| 现金计算漂移 | 浮点数累加导致现金与持仓市值对不上 | 用整数（分）记账，或定期对账 |
| 佣金计算边界 | 佣金最低 5 元，小额交易时佣金占比极高 | 检查每笔交易的佣金占比 > 0.5% 告警 |
| 不可交易状态未识别 | 停牌股票无法买卖但持仓中 | 每轮检查持仓股票的停牌状态 |

### 11.7 状态持久化设计

V1 每 2 分钟唤醒、跑完即退出，所有状态必须在进程外持久化。这是架构上最脆弱的一环。

**必须持久化的状态**：

| 状态 | 存储位置 | 更新时机 |
|------|---------|---------|
| 持仓明细（代码、数量、成本价、建仓日） | SQLite `positions` 表 | 每笔成交后 |
| 持仓的 peak_price（用于 R2/R3） | SQLite `positions.peak_price` | 每轮盯市后 |
| 建仓日的 ATR 基准 | SQLite `positions.atr_base` | 建仓时 |
| 30 日冷却期记录 | SQLite `cooldown` 表 | 卖出后 |
| 当日已买入数量 | SQLite `daily_state` 表 | 每笔买入后 |
| 当日已卖出数量 | SQLite `daily_state` 表 | 每笔卖出后 |
| 挂单状态（跌停顺延中） | SQLite `pending_orders` 表 | 触发挂单时 |
| 心跳/轮次号 | JSON 文件 | 每轮结束 |

**为什么用 SQLite 而非 JSON**：持仓和冷却期是结构化、可查询、需要事务保证的数据。JSON 适合配置和一次性状态，不适合高频更新的业务状态。

**事务边界**：一次"卖出 + 冷却期记录 + 现金更新"必须在同一个事务中，否则进程在中间崩溃会导致状态不一致。

**验证实验 ENG-04**：在每轮之间 kill 进程，验证重启后状态能正确恢复（持仓、冷却期、当日计数、挂单状态均无丢失）。

## 第 12 章 实盘/模拟盘部署方案

`计划.md` 第 10 节把实盘部署列为可选阶段。本章补充部署中的技术要点和 V1 计划未覆盖的部分。

### 12.1 cron 调度的局限性

V1 计划用 cron 每 2 分钟唤醒。**cron 的精度不可靠**：

| 问题 | 说明 |
|------|------|
| 最小粒度 | cron 精确到分钟，2 分钟间隔在负载高时可能延迟到 3-4 分钟 |
| 无重叠保护 | 上一轮没跑完，下一轮已启动 → 两个进程同时跑 |
| 无错过补跑 | 如果系统关机错过几轮，重启后不会补跑 |
| 无法做交易时段判断 | cron 表达式无法表达"只在交易时段运行"，需要代码内判断 |

**改进：用 systemd timer 替代 cron**：

```
[Timer]
OnCalendar=*-*-* 09:25:00~15:10:00
Persistent=true          # 关机错过的任务在下次启动时补跑
AccuracySec=30s          # 精度提升到 30 秒
Unit=quant-engine.service

[Service]
Type=oneshot
# 单实例保护：如果上一个实例还在跑，systemd 不会启动新的
```

**或者：用独立守护进程 + 定时器**（更灵活）：

```python
# src/live/scheduler.py
import time, signal, threading
from datetime import datetime, timedelta

class TradingScheduler:
    def __init__(self, interval_sec=120):
        self.interval = interval_sec
        self.running = False
        self.pid_file = "/tmp/quant_engine.pid"

    def is_trading_time(self, now):
        """交易时段判断（含午休）"""
        t = now.time()
        return ((time(9,25) <= t <= time(11,30)) or
                (time(13,0) <= t <= time(15,10)))

    def is_another_instance(self):
        """PID 文件检测，防止重复执行"""
        if not os.path.exists(self.pid_file):
            return False
        try:
            pid = int(open(self.pid_file).read().strip())
            os.kill(pid, 0)  # 检查进程是否存在
            return True
        except (ValueError, ProcessLookupError, PermissionError):
            return False

    def run(self):
        while self.running:
            now = datetime.now()
            if self.is_trading_time(now) and not self.is_another_instance():
                with open(self.pid_file, 'w') as f:
                    f.write(str(os.getpid()))
                try:
                    run_engine_round()
                finally:
                    os.remove(self.pid_file)
            time.sleep(self.interval)
```

### 12.2 双源切换的实现细节

V1 计划新浪 + 腾讯主备切换。实测结果（见 `调研来源记录.md`）：

- **腾讯 `qt.gtimg.cn`**：HTTP 200 可达，无额外请求头要求
- **新浪 `hq.sinajs.cn`**：HTTP 403，需带 `Referer: https://finance.sina.com.cn`

**切换策略需要三层判断**，而非简单的"主源失败换备源"：

```python
class DualSourceSnapshot:
    def fetch(self):
        # 第 1 层：主源请求是否成功
        try:
            df = fetch_tencent()
            if self.validate(df):        # 第 2 层：数据是否合理
                return df, "tencent"
        except Exception as e:
            log(f"tencent failed: {e}")

        # 第 3 层：备源
        try:
            df = fetch_sina()
            if self.validate(df):
                return df, "sina"
        except Exception as e:
            log(f"sina failed: {e}")

        raise AllSourcesFailed()

    def validate(self, df):
        """合理性校验"""
        checks = [
            len(df) > 3000,                       # 行数
            df["close"].between(0.1, 10000).all(), # 价格范围
            df["close"].notna().all(),            # 无空值
            abs(df["pct_chg"].mean()) < 10,       # 平均涨跌幅不离谱
        ]
        return all(checks)
```

**关键点：validate 比"请求是否成功"更重要**。接口返回 200 但内容为空、或返回了 HTML 错误页（而非数据）的情况比请求失败更常见。

### 12.3 成交推送的幂等性

飞书推送可能重复（网络重试、推送服务重发）。如果成交记录被推送两次，会误导操作。

```python
def notify_feishu(trade, session):
    """带幂等保证的推送"""
    dedup_key = f"{trade.code}_{trade.ts}_{trade.side}"

    if session.query(SentNotification).filter_by(key=dedup_key).first():
        return  # 已推送过，跳过

    try:
        send_to_feishu(trade)
        session.add(SentNotification(key=dedup_key, ts=trade.ts))
        session.commit()
    except Exception:
        session.rollback()
        raise
```

### 12.4 模拟盘 vs 实盘的差异清单

| 维度 | 模拟盘 | 实盘 |
|------|--------|------|
| 撮合 | 假设以限价成交 | 挂单后可能不成交（滑点、排队） |
| 涨跌停 | 检查封单判断 | 需看实际排队深度 |
| 部分成交 | 假设全额成交 | 大单可能只成交一部分 |
| 资金 | 无约束 | 受券商资金划转限制 |
| 佣金 | 固定费率 | 可能有最低收费、规费差异 |
| 时间 | 可以重跑、回放 | 不可重来 |

**V1 是模拟盘，这个定位是准确的**。切换到实盘时，最大的风险不是策略逻辑，而是**撮合假设的失效**——模拟盘假设"限价单一定能成交"，实盘中这可能不成立。

### 12.5 部署前置检查清单

上线前必须逐项验证：

```
□ 数据源连通性（主源、备源分别测试）
□ 数据合理性校验（validate 函数在异常数据上的表现）
□ 状态持久化（kill 进程后重启能恢复）
□ PID 文件防重复（手动启动两个实例测试）
□ 看门狗独立运行（kill 主引擎，看门狗应告警）
□ 看门狗自身的监控（kill 看门狗，外层应告警）
□ 飞书推送连通性（测试消息能送达）
□ 时间闸门（非交易时段不应产生交易）
□ 跌停挂单逻辑（构造跌停场景测试）
□ 冷却期生效（卖出后立即再买同一只应被拒）
□ 磁盘空间（历史数据增长监控）
□ 时钟同步（NTP，避免时间漂移）
```

### 12.6 回测 → 模拟盘 → 实盘的验证阶梯

```
第 1 级：历史回测（日线）
  目标：验证策略逻辑无未来函数、参数合理
  局限：日线无法捕捉日内执行细节

第 2 级：历史回测（分钟线）
  目标：验证日内执行假设（09:40 后开仓、2 分钟轮询的实际影响）
  局限：分钟线数据量大（5400 只 × 240 分钟 × 100 日）

第 3 级：模拟盘（真实行情，模拟撮合）← V1 所在阶段
  目标：验证系统工程可靠性（无人值守、数据通路、状态持久化）
  局限：撮合假设仍非真实

第 4 级：纸交易（真实行情，真实下单接口，不接资金）
  目标：验证真实成交的滑点和部分成交
  局限：无资金风险，心态不同

第 5 级：小资金实盘
  目标：验证资金约束、心理影响
  前提：第 1-4 级全部通过
```

**V1 停在第 3 级，这是合理的**。从第 3 级跳到第 5 级的常见失败原因是跳过了第 4 级——没有验证过真实下单的成交质量。

## 附录 C：数据流水线实现规范

### C.5 两阶段流水线

```
阶段一（离线，每日收盘后跑）：
  1. 拉取全市场快照 → data/snapshot/{date}.parquet
  2. 计算市场状态 → data/sentiment/{date}.parquet
  3. 对快照跑硬过滤 → 候选池600只
  4. 对候选池逐只加载日线 → 计算衍生指标 → 跑4个形态检测器
  5. 输出信号 → backtest/results/signals/{date}.parquet

阶段二（backtrader，按日推进）：
  1. 读取 signals/{date}.parquet → 获取当日所有候选
  2. 对每个策略分别创建 Cerebro，注入候选股票的日线数据
  3. 按日执行：先卖后买，受情绪闸门/仓位上限约束
  4. 输出 trades.csv/daily_nav.csv/positions.csv/metrics.json
```

### C.6 增量更新策略

```
对每个交易日 t：
  1. 检查 data/daily/{code}.parquet 的最后日期
  2. 如果最后日期 < t，拉取 t 日的 OHLC 并追加
  3. 重新计算衍生指标（追加后需重算最后 60 行）
  4. 快照和情绪数据同理增量更新
```

**重算范围**：追加 N 行后，只需重算最后 `max(60, N+10)` 行的衍生指标。

### D.4 自定义 Portfolio（替代 backtrader broker）

**建议用自定义 Portfolio**，原因：

1. backtrader broker 不直接支持"涨跌停检查"和"价格过期检查"（V1 铁律 F1/F2）
2. backtrader order 机制是"下单后等成交"，而 V1 需要"检查条件后立即成交"
3. 自定义 Portfolio 完全可控，调试更容易

```python
class CustomPortfolio:
    def __init__(self, initial_cash):
        self.cash = initial_cash
        self.positions = {}

    def buy(self, code, price, qty, ts):
        cost = price * qty * (1 + COMMISSION)
        if cost > self.cash: return False
        self.cash -= cost
        self.positions[code] = Position(code, price, qty, ts)
        return True

    def sell(self, code, price, qty, ts):
        if code not in self.positions: return False
        proceeds = price * qty * (1 - COMMISSION - STAMP_TAX)
        self.cash += proceeds
        del self.positions[code]
        return True
```

| 组件 | 防未来函数规则 |

| MA | `rolling(n, min_periods=n).mean()`，前 n-1 行 NaN |
| MACD | EMA 用 `adjust=False, min_periods=n` |
| 60日新高 | `rolling(60).max().shift(1)`，不含当日 |

| 情绪分位 | `rolling(500)` 窗口，含当日 |

### G.2 V2 的核心设计原则

1. **市场状态优先于个股形态**。V1 的失败不是因为形态选错，而是因为没判断市场。V2 的第一层应该是市场状态，第二层才是个股形态。

2. **风控参数按策略逻辑区分**。趋势策略（缩量回踩、强者恒强）需要宽止损给波动空间；反转策略（超跌反弹）需要紧止损快速认错。用同一套参数是 V1 的缺陷。

3. **波动率归一化贯穿全链路**。跌幅、止损、仓位都应该用 ATR 归一化，而非固定百分比——这是处理"不同股票波动特性不同"的根本方法。

4. **打分系统不承载预测功能**。如果打分无法在历史数据上证明预测力，就不应该作为交易决策的依据。

5. **改进用"降低亏损"而非"提高收益"衡量**。V1 的价值在于用真实数据验证了什么不行。V2 的合理目标是把四个账户的合计亏损从 17% 降到 10% 以内，而不是追求正收益。

6. **工程可靠性是前提条件，不是加分项**。五条铁律的深化（第 11 章）应该在策略改进之前完成——一个会静默失效的系统，跑什么策略都不可信。
